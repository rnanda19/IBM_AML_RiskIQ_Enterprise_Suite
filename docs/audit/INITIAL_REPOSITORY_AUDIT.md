# Initial Repository Audit

Phase 1 of the "Global Benchmark Review" upgrade program (external ChatGPT review + blueprint,
provided 2026-10-10). This is a real inspection of the repository as it exists on disk right now --
commands run, outputs read, nothing inferred from README claims alone. Where I could not verify
something (it requires executing the real data/notebook pipeline), that is stated explicitly rather
than assumed either way.

## What exists, verified by direct inspection

- **Real data on disk**: `data/raw/` contains the actual IBM AML dataset files for all 5 published
  variants (HI-Small, HI-Medium patterns, HI-Large, LI-Small, LI-Medium, LI-Large) as CSV + Parquet,
  not stubs. `data/processed/` has cached raw-string parquet per mandatory tier.
- **Real notebook logic, as `.py` single-cell scripts, not `.ipynb`**: every BP1-BP5 has 4 real stage
  scripts (`01_business_understanding_policy`, `02_feature_engineering_modeling`,
  `03_statistical_validation_deployment`, `04_compliance_impact_reporting_packaging`), all tracked in
  git. Only BP6 has an actual `.ipynb` (`notebooks/bp6_enterprise_compliance_monitoring/...ipynb`).
- **Real trained model artifacts committed**: BP1/BP2/BP4/BP5's champion `.pkl` files are explicitly
  whitelisted in `.gitignore` (which otherwise excludes `models/**/*.pkl`) and are present on disk with
  real byte sizes and SHA-256 hashes recorded in `MODEL_REGISTRY.md`. BP3's champion is a rule (JSON),
  not a trained model, consistent with `RULE_CARD.md`.
- **Real test suite**: 66 tests, all passing (`pytest tests/ -q` -> `66 passed`; 25 unit, 41
  integration). `tests/unit/test_security.py` and the per-BP `tests/integration/<bp>/` directories are
  real, not placeholders.
- **Real static analysis, currently clean**: flake8 clean, black clean, isort clean, mypy clean (0
  errors / 16 source files), bandit: 0 Medium/High findings, 7 Low-severity/High-confidence
  informational findings (the `pickle.load` calls on each service's own trusted model artifact --
  `# nosec B301`-annotated with a trust-boundary justification each, not a blanket suppression).
- **Real API hardening**: `src/aml_riskiq/serving/_security.py` (API-key auth, token-bucket rate
  limiting via `slowapi`, structured JSON audit logging) is shared by all 5 FastAPI scoring services.
  As of this audit it also has a fail-closed production gate (`AML_RISKIQ_REQUIRE_AUTH`, added this
  session) that makes a missing `AML_RISKIQ_API_KEYS` a hard startup failure when explicitly enabled,
  rather than only a warning.
- **Real CI**: 5 workflows (`ci.yml`, `code-quality.yml`, `codeql.yml`, `docker-verify.yml`,
  `pages.yml`), none using `|| true` to mask a real failure (confirmed by direct read of each file).

## What does NOT exist yet (gaps, not hidden)

- **BRD/FRD/RTM are stub placeholders.** `docs/BRD/README.md`, `docs/FRD/README.md`,
  `docs/RTM/README.md` each contain only `# <name> - to be filled during Sprint 1/2`. There has never
  been a formal requirement-traceability artifact for this platform before this audit.
- **No RBAC / role-based access control anywhere in `src/`.** `_security.py` is single-tier (a caller
  either has a valid API key or doesn't) -- there is no investigator/analyst/admin/auditor distinction
  at the API layer. The external review's finding here is accurate.
- **No live monitoring service, `/metrics` endpoint, or scheduled job.** Confirmed by grep: no
  `prometheus`, no `/metrics` route, no `apscheduler`/`celery`/cron wiring anywhere in `src/`.
  `MONITORING.md` already discloses this ("What this is NOT (yet)") -- the gap is real and already
  honestly documented, not newly discovered.
- **BP2's scoring service has a real, reproduced startup crash.** `docker-verify.yml`'s own header
  comment (and `ROADMAP.md`) documents a `KeyError` at import time because the committed validation
  report predates a code change that now reads two keys (`champion_needs_rf_impute`, `rf_impute_value`)
  the report doesn't have. BP2 is excluded from Docker CI verification as a result. Fix requires a real
  re-run of BP2 Notebook 3 to produce the missing train-derived value -- it cannot be invented.
- **BP3's near-train-flagged lookup Parquet does not exist on disk.**
  `models/bp3_network_graph_intelligence/` contains only the rule JSON, `.gitkeep`, and `README.md` --
  the lookup artifact BP3's scoring service needs is absent. Same root cause class as BP2: only a real
  notebook re-run produces it.
- **No independent/external validation of any reported metric.** Every PR-AUC/recall/F1 number in
  `BENCHMARKS.md` traces to this project's own saved validation-report JSON files, generated by this
  project's own notebook runs on the IBM synthetic dataset. That is real, reproducible evidence of this
  project's own pipeline -- it is not independent bank-data validation, and `BENCHMARKS.md` does not
  claim to be.

## Standing constraint this audit surfaces for Phases 2-9

This project has an existing, explicit standing rule (documented in `ROADMAP.md`, `LESSONS_LEARNED_APPLIED.md`,
and reaffirmed repeatedly across this session's history): **I do not execute the real notebook/data
pipeline.** I write and verify code, fix bugs, write tests against fixtures, and audit/document -- I do
not run `02_feature_engineering_modeling` or `03_statistical_validation_deployment` against the real
31M-row LI-Medium dataset myself, because that is exactly the kind of "silently worked around" execution
this project's own governance history was built to prevent (every number in this repo is meant to trace
to a run the user can point to and reproduce, not one I ran unsupervised).

The user's own 9-prompt blueprint explicitly asks for things that require that kind of execution:
re-running BP2/BP3 to produce missing artifacts (Prompt 2), comparing XGBoost/LightGBM/RandomForest and
recalibrating thresholds (Prompt 4), leakage audits "run" against real data (Prompt 3). These are real,
valuable asks -- they are also multi-hour, compute-heavy jobs against real data that change this
platform's actual reported numbers, which is squarely the kind of change this project's standing rule
reserves for a real, user-run notebook execution. I flag this now, before Phase 2, rather than either
silently skipping those items or silently overriding a rule this project set for itself.
